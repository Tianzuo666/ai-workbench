# GitLab MR 只读审查

审查请求授权读取指定 MR 的元数据和差异，不自动授权读取任意本地文件、修改工作区、运行验证或在远端评论。

## 连接与范围

- 从 MR URL 解析实例、含子组的项目路径和 MR iid，保留原实例。项目路径按 API 要求编码，不从目录名猜项目。
- 优先使用现有只读连接、CLI 或 API。使用 PAT 时从本地环境/安全存储取值，不要求在聊天粘贴，不写文件或输出认证头。
- 缺少连接时说明需在本地配置的项。默认校验 TLS；自托管证书问题应使用受信任 CA，不默认加 `-k`。
- 不 checkout、pull、stash、reset、创建分支或自动 fetch。需要本地源码时先确定用户提供的仓库路径；不固定桌面或磁盘位置。

## 取得完整差异

1. 读取标题、描述、源/目标项目与分支、当前 head SHA 和 diff_refs。
2. 根据 [API 参考](references/gitlab-api.md)分页读取差异，记录新增、删除和重命名，核对截断、折叠、大文件和接口限制。
3. 分块读取已取得的全部差异，不根据第一页、摘要或文件数声称完成审查。
4. 需要完整文件时，先列出拟读取的路径和版本，获得相应批准。优先读取 MR 对应 SHA 的文件或已存在的 Git 对象，不改变工作区分支。
5. 本地内容与 MR head 不一致时，说明版本差异，不把工作区当前文件当作 MR 内容。MR 更新后重新核对受影响部分，保留本次审查依据的 SHA。

数据未准备完成、权限不足、差异被限制或未获准读取上下文时，明确覆盖范围与未知项。不能取得完整差异时不宣称完整审查通过。

## 审查与输出

关注改动引入的数据正确性、安全、接口与消费者、状态/并发、兼容和实际性能问题。仅在具体变更需要时看相关组件、路由或调用方，不机械全项目扫描。

先输出编号问题，每项含 P0/P1/P2、文件及对应版本的行号、触发条件、影响、依据与建议。不要虚构未读消费者，也不把已有无关风格问题当作本次缺陷。

附 MR 链接、源/目标分支、本次 head SHA、读取范围、未读内容与未运行检查。无发现时说明“在已读范围未发现可行动问题”，保留覆盖限制。

默认在聊天交付。用户要求报告文件时写入指定位置或业务仓库外，不自动写进业务仓库。临时差异文件放本次独立临时目录，只清理自己创建的文件，不使用固定全局文件名。

修改代码、运行验证、提交评论、批准或合并 MR 都需用户另外明确授权；本技能自身不执行远端写入。若用户要本地修复，转入明确的实施任务，不以审查为由自动改动。
