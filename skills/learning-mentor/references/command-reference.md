# 学习命令参考

这些前缀是意图表达的快捷方式，接受等价自然语言。读取与当前请求有关的行即可。状态保存在用户指定的 MEMORY.md；学习笔记使用单独指定的产物路径。

| 命令 | 行为 | 写入与权限 |
|---|---|---|
| `main:` | 从当前已确认位置教一个小步骤 | 默认不写、不运行 |
| `branch:` | 回答相关支线，保留主线位置 | 不写 |
| `status:` | 展示轨道、阶段、任务、证据、阻塞和下一步 | 不写；没有可信状态时直接说明 |
| `next:` | 开始已排定的下一项 | 不凭命令认定当前已掌握；移动持久指针仍须确认 |
| `checkpoint:` | 用解释、练习、代码或产物核对成功条件 | 只给评估和状态变更预览，确认后才记录 |
| `review:` | 复习已确认内容，检查薄弱理解 | 不自动回退或重写进度 |
| `note:` | 创建或增量更新本条消息指定的 Markdown 笔记 | 仅对应笔记；preview 不写 |
| `adjust:` | 提议调整路线、节奏、任务大小 | 确认后记录 |
| `track:` | 列出、提议、建立、切换或暂停长期轨道 | 不因短问答建轨道；确认后记录，最多一个 active |
| `auto:` | 对本条请求实施文件修改 | 不含运行/验证，后续消息无效 |
| `verify:` | 执行本条明确指定的检查 | 不含文件修改或额外检查，后续消息无效 |
| `context:` | 评估连续性风险 | 不写，不捏造 token 占比 |
| `handoff:` | 准备交接预览 | 确认交接并记录后才写入记忆 |
| `resume:` | 对照最新可信状态与交接继续 | 无状态时先确认目标与基础，不套用导入进度 |
| `help:` | 展示命令或解释指定命令 | 不写 |
| `evolve:` | 提议导师协议或技能变化 | 说明问题、范围、取舍；确认后修改，验证另获授权 |

## 确认与记录

“确认记录”“确认交接并记录”“确认采用并更新技能”是明确确认的例子，普通自然语言同样有效，不要求固定口令。记录内容必须清楚，不能从“继续”推导出新的已掌握结论。

用户已明确要求写入无歧义的状态时，不重复询问同一次确认。写入前读取相关节和 revision，修改确认范围并增加 revision；目标发生变化时先说明冲突。

## note 的目标与边界

显式 `.md` 路径优先于已确认默认路径；临时路径不自动成为以后默认位置。`note: set-default <路径>` 需要确认后更新记忆中的笔记位置。多个目标含糊时先询问。

读取现有笔记并保留用户内容，按主题整合，不整篇覆盖。必要的大范围重组先预览。区分已修正、待复习和待验证，不凭未教内容推断用户“不懂”。

`note:` 不更新进度、轨道、内部交接，不运行命令，也不扩展到其他文件。完整答案仍遵守“用户明确要求才给”的教学约定。

## 最小交接内容

当前目标与已确认位置、完成证据、薄弱点或未知项、相关文件、实际检查结果、下一步及完成条件。交接记录中不保存临时权限、凭据或完整聊天。
