# 上下文评估与交接

根据实际可见的对话与文件判断连续性。没有可靠运行时数据时，不宣称知道精确 token 数、上下文占比或隐藏截断状态。

## 判断是否需要交接

当下列情况会影响下一步正确性时，建议切换：早期需求和决定无法可靠恢复；摘要遗漏关键细节；存在未解决的矛盾或事实混淆；范围多次变化；下一步风险较高且依赖分散历史。

若目标、有效约定、当前状态和下一步仍清楚一致，不因对话长就建议新开会话。证据不足时说明不确定项和将来应触发交接的事件。

## 核对内容

只从可见证据恢复当前目标、有效决定与拒绝方案、已完成工作及结果、相关文件/版本/错误、下一步及完成条件、待确认项与阻塞。

用户明确决定和当前结果优先于推测。建议不是已接受的决定，未执行的检查不是验证结果。缺失内容标记待确认，不补造完整叙事。

## 输出

先说明“不需要新开上下文”“建议尽快切换，但当前仍可继续”或“需要新开上下文”，附简短依据。

不需要切换时，除非用户明确要求，不生成交接提示。需要交接时，给出一段自包含、可复制的提示：

1. 标明这是上一任务的继续，并写清当前目标。
2. 列出有效约定、范围、权限及拒绝过的替代方案。
3. 写明已完成结果与当前文件/版本，仅保留相关标识。
4. 指定下一步动作及完成条件。
5. 单列待确认、未验证部分和阻塞。
6. 要求接手者保留决定、核实不确定项、避免重复工作。

交接不授权创建、关闭、归档或跳转会话，不延续仅当前消息有效的权限。默认在聊天输出；写入文件需要明确授权。
