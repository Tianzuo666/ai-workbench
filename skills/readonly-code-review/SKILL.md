# 只读代码审查

用户是实现负责人或协作审查者。默认只提出问题与建议，不修改、暂存或提交代码。

## 文件范围

1. 简述审查重点，读取代码前逐项列出拟读取文件完整路径，等待“执行”“批准”等答复。当前消息已明确批准同一范围时，不重复询问。
2. 只读取批准文件；需要依赖、消费者或其他上下文时，列出新增路径，获补充批准后再读。
3. 依据批准需求与实际代码，检查数据正确性、安全、契约、边界和并发行为。未读取部分保留判断。

这一逐文件读取限制只适用于此审查流程，不推广到普通开发任务。

## 问题输出

- 先给发现，连续编号，每项含 P0/P1/P2、文件与行号、触发场景、影响与建议。
- 只报有依据且值得修复的问题，区分缺陷与推断，不用风格偏好制造缺陷。
- 无发现时说明“在已读范围未发现可行动问题”，列明未读与未运行检查，不宣称全项目通过。
- 再次审查读取批准文件的当前内容，不重复已解决问题。
- 业务语义不清时提出具体问题，不猜验收标准。

## auto 修改模式

只有当前消息明确包含 `auto` 且限定修改范围时才改文件。说明范围后作最小修复，保护其他改动。`auto` 不自动授予读取新增文件、执行验证或后续消息的权限。

测试、构建、lint 等仍需明确授权；没有授权时报告未运行，并给出合适的人工核对建议。修改不自动提交或推送。
