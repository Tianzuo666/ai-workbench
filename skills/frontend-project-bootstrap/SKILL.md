# 前端项目初始化

先只读分析当前项目；用户确认具体方案后，再写入已批准的文档。

## 分析范围

枚举当前项目附加目录及用户指定路径中的仓库。
区分独立 Git 仓库与 monorepo 子项目，避免重复计数。
无法获取完整目录列表时，说明可访问范围并询问缺失路径。

深入分析或修改任何仓库前，读取该仓库实际生效的 AGENTS.md、
AGENTS.override.md 及嵌套规则，包括次要附加仓库；按工具加载机制
处理覆盖关系，不假定同目录两份规则会自动合并。

## 分析流程

检查 package.json、README、锁文件、构建配置、目录结构
和已有架构文档，按需定向阅读源码，跳过依赖和构建产物。

识别：
- 仓库职责、技术栈、包管理器。
- 主应用、微应用、组件库、文档或服务端属性。
- 仓库依赖、应用注册、路由、事件和接口契约。
- 国内、海外、运营、运维等版本的配置与业务差异。
- 共享逻辑和重复实现。

重要结论附文件依据，区分事实、推断和未知项。
不要仅凭仓库名称推断关系；文档与代码冲突时报告冲突。

## 输出

用中文输出：
- 仓库清单。
- 仓库关系和调用方向。
- 主仓库建议及理由。
- 共享逻辑与重复逻辑。
- 环境差异。
- 风险和未知项。
- 建议创建或更新的 AGENTS.md 和架构文档，
  包括具体路径、用途和内容提纲。

先在聊天中呈现结果，用户确认前不创建或修改文件。

用户批准后，只写入已确认的文档和 AGENTS.md。
保留现有有效规则和用户内容，优先复用现有文档。
完成后列明修改文件及仍待确认的事项。

## 操作边界

未经用户另外明确批准，不运行安装、构建、测试、
lint、类型检查、格式化或开发服务器。

不读取或输出 .env、密钥、令牌、凭据及其他敏感信息。

不修改业务代码，不自行提交、推送或创建 PR，
不更改项目配置。

本 Skill 仅使用指令，无脚本、素材或外部依赖。
