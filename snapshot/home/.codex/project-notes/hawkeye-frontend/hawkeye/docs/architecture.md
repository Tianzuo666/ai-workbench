# hawkeye 微信小程序架构说明

## 项目职责

本仓库是独立发布的微信小程序运营客户端。虽然 `package.json` 仍保留“微信产测小程序”的历史描述，但当前 `app.json` 和源码已经覆盖运营首页、设备、商品、库存、订单、平台、资产、销售分析和生产测试等业务。

## 运行形态

项目使用微信小程序原生页面和组件模型，由微信开发者工具加载 `project.config.json`。它不是 Vue 应用，也不是另外两个 H5 仓库的微应用。

当前源码中没有发现 WebView、micro-app、`postMessage` 或对应消息监听，因此与 H5 客户端之间不存在已确认的直接运行时调用。

## 目录结构

| 目录或文件 | 职责 |
| --- | --- |
| `app.js`、`app.json`、`app.wxss` | 小程序入口、全局配置与样式 |
| `pages/` | 主包页面 |
| `packageOperator/` | 运营商相关业务分包 |
| `packageOperatorDevice/` | 设备管理分包 |
| `packageOperatorInventory/` | 库存和补货分包 |
| `packageOperatorOrder/` | 订单分包 |
| `packagePlatform/` | 平台业务分包 |
| `packageCharts/` | 销售分析和图表分包 |
| `packageUnmannedStore/` | 无人店分包 |
| `components/` | 全局复用组件 |
| `behaviors/` | 页面和组件公共行为，包括列表加载能力 |
| `api/` | 按业务域组织的后端请求 |
| `store/` | 跨页面共享状态 |
| `utils/` | 请求封装、环境配置和通用方法 |
| `custom-tab-bar/` | 自定义底部导航 |
| `docs/miniprogram-ui-spec.md` | 页面、组件、状态和交互规范 |

`app.json` 是页面与分包注册的事实来源。新增页面时必须同步维护对应分包配置和页面 JSON。

## 页面与公共能力

- 页面和组件优先复用 `components/`、业务分包公共组件、`behaviors/` 和全局样式。
- 列表页优先使用 `behaviors/pageLoading.js` 统一处理首次加载、下拉刷新、分页和空状态。
- Vant Weapp 组件在全局或页面 JSON 中注册；使用前以组件源码和现有同类型页面为准。
- 计算属性和监听通过 `miniprogram-computed` 提供。
- 部分共享状态使用 MobX 小程序绑定能力，修改状态归属前先检查 `store/` 及页面绑定方式。
- 页面和组件的视觉、交互及文件头要求统一遵守 `docs/miniprogram-ui-spec.md` 和根目录 `AGENTS.md`。

## API 与环境

`api/` 按业务域封装请求，底层请求与服务地址由 `utils/` 中的公共能力管理。开发环境地址放在未跟踪的本地配置中，不应提交或写入架构文档。

小程序与两个 H5 客户端共同消费部分后端领域，例如：

- 员工登录和组织切换。
- 设备列表、设备详情和设备控制。
- 商品、仓库、库存和补货。
- 文件上传、状态枚举和权限标识。

接口 URL 相同不代表页面实现可以共享。跨端变更应同步字段和业务规则，小程序 UI 继续使用原生实现。

## 与其他仓库的边界

| 仓库 | 关系 |
| --- | --- |
| `hawkeye-southeast-asia` | 海外 Vue Web/移动端应用；共享部分后端契约，无直接运行时调用 |
| `ant` | 国内 Vue H5 和生产测试微应用；共享部分国内业务及接口，无直接页面复用 |

当登录、设备详情、上传、状态枚举或权限字段变化时，需要检查三个客户端。仅涉及小程序布局、组件事件或分包导航时，不应顺带修改 H5 仓库。

## 变更原则

- 新增或修改页面前先完整阅读 `docs/miniprogram-ui-spec.md`。
- 优先从规范中选择同类型参考页面，再核对组件源码和相邻业务实现。
- 表单必须处理校验、提交 loading、防重复提交和失败后的状态恢复。
- 修改公共组件 API 时，同步更新所有消费者和 UI 规范中的示例。
- 修改接口参数、返回字段或枚举时，记录跨端影响，不在小程序内私自定义另一套含义。
